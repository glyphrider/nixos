# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A NixOS flake configuration for a single host named `stealth` (Hyprland desktop, AMD GPU, btrfs on a single disk with GRUB/EFI boot). There is no application code, build system, or test suite — this is declarative system + home-manager configuration, and "correctness" means "the flake evaluates and the system activates cleanly."

## File layout

- `flake.nix` — flake inputs/outputs. Defines the single `nixosConfigurations.stealth` system, wires in `home-manager` as a NixOS module, and pins several flake inputs.
- `configuration.nix` — system-level NixOS config. See @claude-system.md.
- `home.nix` — home-manager config for user `brian`. See @claude-home.md.
- `hardware-configuration.nix` — machine-generated by `nixos-generate-config`; treat as read-only (do not hand-edit; regenerate instead if disk layout changes).
- `wallpapers/` — static image assets referenced from `home.nix`.

## Commands

- Apply changes to the running system: `nixos-rebuild --sudo --flake . switch` (run from the repo root). Do **not** use `sudo nixos-rebuild switch` — the flake needs to be pointed at explicitly.
- Check that the flake evaluates without switching: `nixos-rebuild --sudo --flake . build` or `nix flake check`.
- Update all flake inputs: `nix flake update`. Update a single input: `nix flake lock --update-input <name>`.
- Format Nix files with `nixfmt` or `nixpkgs-fmt` if invoked explicitly; the repo has no enforced formatter/CI, so match the existing style in the file you're editing (2-space indent, attribute sets `{ ... }`).

## General conventions

- **Comments explain the "why," not the "what."** Several config blocks carry multi-line comments documenting a specific hardware/software quirk that motivated the setting. When editing near these, read the comment first — the setting is almost always compensating for a specific bug, not a stylistic choice — and keep/update the comment if the reasoning changes.
- `system.stateVersion` / `home.stateVersion` (currently `"25.11"`) must not be bumped casually; it controls migration behavior across NixOS releases, not "what version to target."
- Hardcoded values that look like they should be variables (IPs, MAC addresses, extension IDs) are tied to this specific physical setup — don't genericize them without asking.
